# 18 — JWT Expired Recovery في Anime Library (2026-11-14)

## المشكلة التي عالجناها
ظهور `JWT expired` تحت أزرار `Not on my list` و`Favorite` في صفحة تفاصيل الأنمي، وتعطل تحديث المكتبة بعد انتهاء صلاحية رمز جلسة Supabase.

## التعديلات
- `anime-library.js` يكشف استجابة JWT المنتهية في استعلامات المكتبة وحفظ/حذف الحالة والمفضلة.
- عند خطأ JWT يستدعي `auth.refreshSession()` مرة واحدة، ثم يعيد استعلام Supabase مرة واحدة فقط (الحفظ والتحديث idempotent عبر مفتاح المستخدم/الأنمي).
- يراجع `getSession()` قبل الحفظ ويتأكد من مطابقة مالك الحساب، ولن يرسل كتابة لحساب آخر إذا تغير المستخدم أثناء التجديد.
- في حال عدم إمكان تجديد الجلسة يعرض رسالة مفهومة ورابط `Log in again` ويُعطّل أزرار الكتابة بدل إظهار الخطأ التقني الخام.
- تحديث نسخة تحميل ملف `anime-library.js` في `my-anime.html` و`profile.html` و`anime-detail-auth-v22.js` لتجاوز كاش ملفات JS القديمة.
- لا تغيير في بيانات Supabase أو RLS أو SQL أو مكتبة الحلقات.

## اختبار محلي
`node PROJECT-DOCS/TESTS/library-jwt-refresh-smoke.cjs`

المحاكاة تغطي: JWT منتهي عند upsert، JWT منتهي عند delete، فشل refresh، تغير الحساب خلال refresh، وتحديث مراجع السكربت في HTML. بالإضافة إلى اختبارات PWA السابقة.

## بعد النشر
1. اختبر `anime-details.html` بحساب مسجل، وغيّر Watching/Favorite وتأكد أن الحفظ يعمل.
2. اترك الصفحة مفتوحة فترة طويلة ثم جرّب تحديث المفضلة، وتأكد من عدم ظهور نص JWT الخام.
3. إذا فشل refresh فعلًا (الـrefresh token ملغى أو خرج الحساب) يظهر `Log in again`؛ سجّل دخولًا جديدًا ولا تغيّر جدول المكتبة.
4. تحقق على متصفح الكمبيوتر وفي تطبيق Add to Home Screen. لا يمكن ضمان أن التوكن يُجدد حيًا دون اختبار Supabase المنشور.

## حدود التنفيذ
لم يتم تسجيل الدخول لحساب المستخدم أو اختبار Supabase/Cloudflare حقيقيًا. إذا كانت سياسة الجلسة في Supabase تمنع التجديد، سيحتاج المستخدم إلى إعادة تسجيل الدخول.
