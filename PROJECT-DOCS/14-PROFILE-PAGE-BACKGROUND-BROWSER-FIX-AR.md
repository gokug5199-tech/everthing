# إصلاح خلفية صفحة Profile في المتصفح — 2026-11-14

## لماذا اختفت؟
- نظام `profile-page-background.js` يحفظ مسار الصورة ويحمّلها من Supabase Storage باستخدام signed URL، ويضعها على `body.has-page-background` في المتغير `--profile-page-image`.
- `profile-v9.css` كان يستخدم `background-image` من دون `!important` على سطح المكتب.
- ملف `te-unified-theme-v12.css` اللاحق يعيد تعريف `background` مع `!important` لجسم صفحة Profile، فيلغي صورة خلفية المستخدم عند فتح الموقع في المتصفح.
- في بعض أحجام الجوال، قاعدة منفصلة تعيد الصورة، لذلك بدت المشكلة مرتبطة بوضع المتصفح وليس التخزين.

## التعديل
1. جعل `background-image` في `profile-v9.css` يحتفظ بالأولوية على إعداد خلفية الثيم العام، دون تعطيل ألوان الثيم عند عدم اختيار صورة.
2. إضافة قاعدة محددة لوضع PWA standalone حتى لا يتغلب خلفية app shell على صورة المستخدم.
3. تحديث إصدار `profile-v9.css` في `profile.html` لإبطال كاش CSS القديم.
4. لم يتغير منطق رفع/حذف الصورة أو روابط signed URL أو سياسات Supabase، ولا بطاقات البروفايل.

## اختبار بعد رفع GitHub/Cloudflare
- افتح Profile في متصفح كمبيوتر بعد تسجيل الدخول: يجب ظهور صورة خلفية الصفحة خلف كل البطاقات.
- افتح Profile في متصفح الجوال العادي: يجب ظهور الصورة.
- افتح Profile من أيقونة Add to Home Screen: يجب ظهور الصورة مع الحفاظ على شريط التطبيق.
- اختر صورة جديدة، ثم حدث الصفحة، وتحقق من بقاءها في الحالات الثلاث؛ عند Remove background يجب الرجوع لخلفية الثيم العادية.
- صورة **Profile card background** مستقلة عن **Page background**؛ يجب أن تعمل كلتاهما.
- جرّب حساب مستخدم آخر: لا ينبغي أن يرى خلفية حساب غيره؛ تحقّق من RLS في بيئة الإنتاج.

## حدود الاختبارات
- تم فحص مواضع القواعد وخصوصيتها وتصادمها، وفحص بنية CSS وملف HTML وفحوص JavaScript المحلية.
- لا يوجد وصول لحسابات Supabase الفعلية أو اختبار مباشر على Cloudflare أو جهاز حقيقي.
- لا SQL جديد، ولا تغيير لقيم قاعدة البيانات.
